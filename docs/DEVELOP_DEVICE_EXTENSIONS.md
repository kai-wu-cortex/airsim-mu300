# develop：设备扩展与冲突检查

本轮以 `shangjie1998/airsim-f50-openwrt` 的
`4df1116997425ae4b91d44cd6121bb25c836162c` 为功能参考，在本项目独立实现。
不修改 AirSIM iOS/Android 或用户的上游工作树，不整体覆盖参考仓库的旧 Agent。
当前为开发代码，未发布。2026-11-11 经用户授权安装到 USB 连接的 U30 Air；基础检查通过，新增功能的人工验收待完成。

## 功能与边界

| 功能 | 已接入 | 边界 |
|---|---|---|
| 内核信息与选择 | 运行/引导记录、配置摘要、已存在内核包、手动命令确认 | 不在页面直接换内核；版本号不等于兼容性 |
| 音频组件目录 | 固定清单、内核/配置/包哈希检查、后台安装与状态 | 仅已有 U30 5.4 构建可进入原有完整预检；6.18/7.3 禁用 |
| 配对设备 | 指纹、最近活动、移除关联授权 | 活动为本次服务启动以来的认证，纯云端不计入 |
| 备份与恢复 | 配置、身份、配对、通知和蓝牙偏好；恢复前副本 | CID＋设备树序列号绑定；包含密钥；不含系统网络、固件、短信和音频 |
| 联网 | 蜂窝、Wi-Fi、蜂窝＋热点；扫描、连接、忘记 | 仅已识别的 UCI 布局；保留仅包含 usb0 的 br-lan；失败回退 |
| Wi-Fi 管理访问 | 专属 HTTP/HTTPS 入站规则开关 | 不放开 SSH；关闭只撤销本功能规则，不替用户改其他规则 |
| 热点流卸载 | 实际 nft 规则检测、5.4 修复、恢复原值 | 非 5.4 不修改；无目标风险不盲改 |
| 蓝牙 | 控制器、电源、扫描、配对、连接、断开、移除；开机偏好 | 复用已有 BlueZ 与配对代理，不自动安装未知 kmod，不宣称 HFP/SCO 音频适配 |
| 通话通知 | Webhook、Bark、Telegram、PushPlus、ServerChan、企业微信、钉钉消息格式 | 默认关闭；公网 HTTPS；事件通知，不是音频转发；签名机器人需兼容端点 |
| 短信 | 独立页、原生收发、批量已读、分批清空、两种收件目录 | 默认旧目录优先；不用符号链接改原生服务；删除不可撤销 |
| 号码、运营商、信号 | 明确的 `86`/`0086` 中国移动号码前缀统一为 `+86`；COPS/CSQ/原生信号补充 | 不猜裸本地号码的国家，不改拨号与短信目标，不显示失败后的旧值 |
| 自检与修复 | 程序、配置、硬件身份、固件存在性、声卡、预留内存与权限 | 自动修复仅为本项目已有普通私有配置的 0600 权限；不伪造 KERNEL 元数据 |
| 外观 | 浅色、深色、系统、间距与透明度 | 浏览器本地保存；只影响本项目 LuCI 页面 |
| 构建一致性 | 菜单/页面依赖/RPC/ACL、版本、ARM64、固定音频摘要 | 自动进入构建流程；不替代 APK 签名校验与实机验收 |

### 蓝牙可选组件尚未开放自动安装

参考项目明确记录：通用软件源的 BlueZ 安装可能带入 6.12.94 kmod，
而目标运行 6.18.60。这不能照搬为跨内核安装功能。
本项目只管理已有可用控制器；控制器缺失时明确拒绝，待取得每个目标的
可复现组件、依赖和 ABI 证据后再开放安装。不会使用忽略依赖或强制加载。

## 内核支持的真实状态

| 组合 | 本轮离线证据 | 安装与验收状态 |
|---|---|---|
| `5.4.254-gb50db5b6224c`＋固定配置 | 保留既有模块与哈希校验链，不改 DSP/PCM 路由 | 历史 U30 双向通话通过；此次新增维护流程尚未实机验收 |
| `6.18.60` | 参考包 25 个 AArch64 模块，vermagic release 与目录一致 | 完整 ABI 和本项目实机验收缺失；不可安装 |
| `7.3.1` | 参考包 25 个 AArch64 模块，vermagic release 与目录一致 | 完整 ABI 和本项目实机验收缺失；不可安装 |

参考两个新内核包没有传统 `__versions` CRC 记录；这可能对应
`CONFIG_MODVERSIONS=n`，**不能单凭这一点认定二进制错误**。
还需要确定完整构建配置、配置摘要计算方法、内核与音频源码及符号/布局的一致性。
参考构建脚本的原始 `.config` 摘要不能直接视为本项目规范化配置摘要。
不移植参考安装器中放宽配置检查或跳过音频探测的流程。

主程序仍按运行时能力检查，不用精确内核白名单阻止独立插件安装。
默认一体包的 5.4 驱动限制继续保留；已有匹配音频栈的其他设备可构建
`AIRSIM_COMPLETE_INSTALL=0` 核心包，但不因此获得硬件通话支持承诺。

## 操作互斥与回退

- 所有设备修改、无线扫描和配置导出：用户主动确认 → 运行/升级共用的独占锁
  → 确认 AirSIM 服务已关闭 → 原生 CLCC 空闲、媒体进程和短信任务检查。
  状态未知时拒绝。已运行的 AirSIM/Watch/Relay 不能被维护按钮抢占。
- 原生短信发送入口增加共享维护锁；服务启动时的音频准备也持有共享锁，
  防止这两个原有入口绕过维护互斥。原生短信任务被接收后仍由 sms_job 阻止维护。
- 耗时操作通过持有同一个继承锁的后台任务执行。页面只轮询结果，不重发操作。
  新页面可恢复观察正在执行的任务；超过五分钟无结果显示未知，不能假装成功。
- 网络配置先在私有临时目录验证，检查外部并发修改，保存原文件，才替换并应用。
  接口未取得地址时回退；回退不完整明确报告，原始配置留在维护目录。
  验证的是接口取得地址，不声称互联网或 IMS 已恢复。
- 原生电话可由设备之外发起，离线测试不能证明所有异步硬件竞争已消除。
  实机验收须覆盖维护期间来电与断网、失败回退、重启恢复；勿在通话期间维护。
- 备份恢复只接受固定字段和文件名、同一硬件身份与一致 Agent 身份；逐项验证，
  拒绝路径穿越/链接目标，失败回退。用户须私密保存备份，不能上传到仓库。
- 短信已读标记绑定文件摘要，ID 复用不会把新短信误标已读。清空绑定预览摘要，
  每条删除前重新核对，出现变化或未知回执就停止；每批最多 20 条。
  原生接口没有原子的“按摘要删除”，因此仍有检查与删除之间的硬件竞争窗口；
  清空只能在无短信到达时人工确认，不承诺保护这一窗口内新占用的槽号。
- 通知只消费 Agent 状态，不另开串口、不控制电话、不持有音频锁。
  服务启动时以现有快照为基线；错误快照不视为挂断，两个可靠缺失快照后才通知结束。
  队列有界，超时不重试；只记录事件类型与投递结果，不记录号码、地址、密钥或响应正文。

Wi-Fi 管理规则显式设置 `src=*` 并限定入站设备，避免无来源规则落入 output 链；
该语义已对照 [OpenWrt firewall4 源码](https://github.com/openwrt/firewall4/blob/master/root/usr/share/ucode/fw4.uc) 核对，仍需实机验证规则与网络布局。


离线模拟覆盖：维护锁跨进程继承、状态未知拦截、备份身份/路径验证、短信到达与
ID 复用、失败不重试、网络回退和 USB 共享桥拒绝、未知内核安装拒绝、通知状态与隐私、
蓝牙最终状态确认、页面确认/双击/任务恢复、原有通话/早期媒体/云端/Watch/配对回归。
不使用真实号码、短信正文、设备音频或设备凭据作为测试数据。

已执行：USB 只读预检、设备内备份、签名候选安装及安装后只读检查。
未执行：设备重启、实际联网切换、蓝牙配对、发送通知、真实短信/通话。
新功能对 U30/F50 的硬件结果均需要另行验收。发布仍须执行 AGENTS.md 的完整发布检查。
