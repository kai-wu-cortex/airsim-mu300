# develop：配对管理、短信发送与信号兼容

参考 [shangjie1998/airsim-f50-openwrt 固定提交 4df1116](https://github.com/shangjie1998/airsim-f50-openwrt/commit/4df1116997425ae4b91d44cd6121bb25c836162c) 的配对列表、短信脚本兼容及信号补充方案，在本项目现有身份、安全和安装流程上实现。感谢 shangjie1998 的 F50 集成工作。

本次只改设备端插件及隔离 Agent 补丁。AirSIM 客户端、上游工作树、当前设备系统均未修改，尚未安装设备或发布。

## 配对设备

入口：**LuCI → 服务 → AirSIM → 配对设备**。

- 列出已有本地／Tailscale 配对记录、SHA-256 指纹、最近认证时间。
- 指纹由解码后的配对密钥计算，不展示密钥或密钥尾部。不具备客户端可信名称时显示“配对记录”，不猜测手机型号。同一手机重复配对可能留下不同记录。
- 最近活动是**本次服务启动后**成功通过局域网、Tailscale 或关联 Watch 控制认证的时间，也包含普通/早期 PCM 握手。120 秒内标记“近期活动”，不宣称持续在线。无活动时明确显示未知，重启后重新统计。纯 Relay 云端通信不能归属到本地密钥，故不计入。
- 列表每 15 秒只读刷新，也可手动刷新；服务未运行时显示无法查询。
- 移除需先选定指纹、再明确确认。列表重排不改变目标；目标消失、状态读取失败时暂停操作。
- 设备端重新检查通话状态；未知、活动通话或音频会话都会阻止移除。持久保存成功后撤销该密钥及关联 Watch／早期媒体授权；存储失败保留原状态。已认证但尚未占用音频的连接在开始音频前再次核对密钥，防止移除后又开新会话。
- 不重启服务、不发挂断命令、不清空短信、不改变其他配对。已进入处理的普通 HTTP 请求不强制中断。**这仅撤销设备端直接配对，不能代替云端账户/Relay 配置管理。**

接口：rpcd `pair_clients` 仅需读取权限；`pair_remove` 需要写权限，以完整 64 位十六进制指纹为目标。内部 HTTP 接口仅挂载回环管理端口，并另外检查来源地址，不开放在 VoWLAN 公共接口。

## 短信脚本兼容

保留原生短信池、发送确认、任务状态、身份字段和未知结果防重发流程，只补充发送参数与回执兼容。

| 模式 | 调用形式 | 说明 |
| --- | --- | --- |
| stdin | `mu300-sms send --stdin` | 号码、换行、正文通过标准输入，原有默认方式 |
| positional | `mu300-sms send NUM TEXT` | 兼容厂商脚本；使用独立参数，不经过 shell 拼接 |

默认自动识别：读取本机脚本中的实际 stdin 选项分支，或明确的位置参数用法/厂商参数错误语句，忽略纯注释。脚本未知、二进制封装或无法识别时保留原 stdin 方式，不凭“缺少 --stdin 字样”就猜测另一种发送接口。

对于无法自动识别的厂商版本，可由设备管理员在 `/etc/mu300/airsim-sms-send-mode` 写入 `stdin` 或 `positional`；`auto` 或文件不存在使用自动模式。该小文件只包含模式名，不含号码或正文；格式错误时停止发送。软件不会自行写入此文件。

位置参数是厂商接口的要求，本机具备进程查看权限的用户可能看到命令参数；实现不记录或向客户端返回原生 stdout/stderr。未知脚本如需使用该模式，先确认其参数契约。

支持最终成功回执 `sent (reference N)` 和 `sent (N)`；允许前面有诊断行、Windows 换行，但必须进程成功退出且最后有效行完整匹配。成功回执后又有错误、超时或退出失败，仍按未知结果处理。**发送之前只选一次模式，绝不在发送失败后换模式重试。** 此功能不表示 F50 收件箱路径或整个硬件适配已经完成。

## 运营商与信号

- 设备空闲时增加 `AT+COPS?` 读取，沿用现有运营商名称规范化。
- 优先使用 `AT+CSQ`；无有效值时使用有超时的只读 `ubus call mu300.modem signal '{"slot":"0"}'`，解析 `sig.rsrp`，其次 `lte.rsrp`。
- 厂商信号只接受 -140 至 -30 dBm 内数值；未知、空字段、格式错误和越界返回未知。
- `signal_dbm` 保留现有字段，新增 `signal_source`（`csq_rssi` 或 `vendor_rsrp`）和 `signal_updated_at`。LuCI 显示 RSSI／RSRP 来源，两者不是同一测量指标，不混用来源标签。
- 运营商读取失败清除旧名称；两路信号都失败清除旧读数，不把旧数值继续当成本次结果。
- 外部查询不持有 modem 状态写锁；通话期间跳过元数据刷新，若采样过程中发现通话开始则丢弃该次提交。通话中的页面可能保留上次空闲采样，时间戳可用于识别。

## 验证边界

自动化覆盖：配对身份稳定、敏感数据不泄漏、读写权限分离、未知通话保护、持久化失败、撤销后延迟音频握手、并发读取/认证/更新；短信模式选择、参数中的引号/换行、两种回执、未知结果不重发；信号来源回退、越界数据及失败清除。

固定 `patches/AIRSIM_BASE` 重新导出隔离 Agent，应用 `patches/AirSIM-mu300.patch`，与开发副本逐文件比较后运行 Go race/vet；插件同样运行 race/vet，所有 Node 测试执行。未进行真实拨号、真实短信、录音或设备安装，F50 与新内核不因此获得实机兼容声明。
