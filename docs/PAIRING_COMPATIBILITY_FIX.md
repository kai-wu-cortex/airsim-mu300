# U30 Air 再次配对被拒绝：设备端修复

2026-11-03，R20 配对修复。只修改独立 U30 Air 集成和固定 Agent 的隔离补丁；AirSIM iOS/Android 及上游工作树不变。

## 现象与原因

用户反馈：输入正确验证码仍提示配对拒绝，切换 iPhone AirSIM 到本地模式后可以配对。

当前客户端的非本地配对请求携带 `live_activity_presentation: "agent_status"`，本地模式在写入该字段之前结束编码。R19 固定的 Agent `pushRegistration` 不包含此字段，严格 JSON 解码返回 HTTP 400。设备已有日志也记录了注册 400 后成功 200 的过程；旧实现自动化测试复现了 `unknown field "live_activity_presentation"`。这并不表示所有配对拒绝都是同一原因，错误验证码、过期会话仍须拒绝。

另外，网关曾直接把 Agent 推送状态中的 `configured` 转给配对客户端。该字段受云功能开关、Relay 地址及设备管理策略影响，即使注册已经成功保存，也可能是 false；客户端会将其解释为配对失败。

原流程在 Agent 接受注册之前写入局域网密钥，失败重试可能消耗客户端名额。

## 修复

- Agent 隔离补丁明确接收并持久化 `live_activity_presentation`，继续转发到 Relay，保留客户端要求的设备状态展示语义。仍严格拒绝未识别字段。
- 只有 Agent 返回成功且状态响应格式有效、网关密钥保存成功后，配对接口才返回 `configured: true`。原推送就绪状态改以 `push_configured` 返回，原云开关、管理限制及推送能力字段保持原样。Agent 的状态接口含义不变。
- 当时提交前检查网关密钥和容量，Agent 接受注册后才写入新密钥，拒绝或异常响应不再新增网关客户端。
- 当时保留已有密钥和 16 个客户端上限，不擅自删除历史配对（2026-11-17 develop 已取消此上限，见下文）。容量检查在实际保存时再次执行；网关写盘失败仍返回失败，不能宣称两个独立状态文件具备跨文件原子事务。

## 验证与边界

自动化覆盖：真实加密请求的首次/再次配对、云推送未就绪、管理策略限制、错误验证码、成功请求重放、无效 Agent 响应、非法密钥与容量已满，以及新增字段经过 Agent 严格解码、持久化、重载后转发到本地 TLS Relay 测试端点。

候选构建标记：`0.1.0-r19-pairing.1`。2026-11-03 经用户授权，已备份并安装到 USB 连接的 U30 Air，只重启 AirSIM 服务，未重启设备。安装前确认通话、媒体及短信任务空闲；安装后两项服务运行，Agent 可达，版本及程序摘要匹配，已有设备身份、配对密钥和服务配置保持原样。配对窗口未开启时，信息接口返回预期的 HTTP 410。

2026-11-03 用户确认：iPhone AirSIM 保持云模式，分别获取新验证码连续配对两次，两次均成功，不再提示验证码错误。云模式重复配对验收通过。

公网推送能力未因本次配对测试完成整体验收；本修复纳入 R20 开发预览；R20 完整 APK 的安装回归与候选二进制的配对验收分别记录。

## 2026-11-14：LuCI 配对码因两端时钟偏差而被隐藏

USB U30 Air 实测：配对接口已有六位码，设备认为窗口仍有效；设备时间比浏览器
所用电脑慢约两小时。概览组件用 `expires_at > Date.now()` 判定，导致有效码显示
为占位符。这是管理页面显示问题，不是验证码生成失败或配对资料丢失。

管理状态中的配对对象增加 `remaining_ms`；LuCI 按设备给出的剩余时间建立浏览器
单调时钟倒计时，同一快照重复渲染不延长截止时间。无效/零/负值不显示验证码，
设备返回空窗口时立即清除。旧服务仍兼容原绝对时间字段。系统首页和 AirSIM
设备概览共用该组件。没有调整设备时钟，也没有放宽配对认证或改变客户端协议。

离线 Go race/vet 和 74 项 Node 测试通过，覆盖浏览器时间领先/落后两小时、到期
清除、异常剩余时间和旧服务兼容。实际配对成功仍须用户在客户端验收。

同日已备份并安装到 USB U30 Air，171 个包文件及新版概览 HTTP 资源哈希核对通过。
通过配对入口重新生成窗口，确认六位码存在、`remaining_ms` 约 120 秒且 Bonjour
已开启；两端绝对时间仍不一致，新页面不再依赖该差值。未输出或保存验证码，
已有配对与设备配置保持原样；客户端配对结果待用户确认。


## 2026-11-17：取消固定配对名额上限（develop 候选）

Cardputer 第 17 次新增配对得到 `gateway_key_storage_failed`，现有设备恰好保存
16 条密钥。新增、重启读入和 Watch 持久授权交集各有一处固定 16 条限制。
本次同时移除三处限制；不改密钥文件格式、不驱逐旧配对、不改 AirSIM 客户端或 Worker。
记录数量仍受设备可用存储、内存和处理能力约束；并发媒体、请求体、重放和验证码尝试
次数的保护继续生效。Watch 的内存/磁盘授权交集改为集合查找，避免记录增多后双重扫描。

后台入口：**LuCI → 服务 → AirSIM → 设备概览 → 管理已配对客户端**。
列表展示全部记录的指纹及本次服务启动后的最近认证活动；只能确认后单独移除选中记录。
读取不删除，移除仍要求已知通话空闲、无音频会话，并撤销该记录关联的 Watch 授权。
设备身份、其他配对和云端配置保留。

已通过认证的配对码仍只用一次。若保存失败，返回 HTTP 500、原机器错误码
`gateway_key_storage_failed`，补充存储检查说明和 `retry_with_new_code: true`。
所有已消费窗口在退出时关闭，旧请求重试返回 410，而非把写盘失败误判为验证码错误；
修复存储后需要获取新码。非法密钥返回 400 `invalid_registration`，不触达云端注册。
云配对仍存在 Agent 注册与本地密钥两个独立存储步骤，不宣称跨文件原子事务。

回归覆盖：64 条密钥持久化与重载认证、单项移除、非法存储拒绝、Watch 超过16条后的
授权与撤销、第17个加密本地配对、写盘失败保留原16条及新码恢复、旧码防重放、
40条管理页面完整显示和确认删除。实机部署与 Cardputer 第17项验收分别记录，不用
离线测试替代真实客户端验收。

回退边界：公开 R25 及更早版本仍拒绝加载超过16条的密钥文件。新增第17条后不能
直接回退旧桥程序；需要保留本修复或使用包含本修复的后续构建。禁止为了回退而
自动恢复旧密钥备份、丢弃新增配对；任何删除仍须用户在后台逐项确认。
