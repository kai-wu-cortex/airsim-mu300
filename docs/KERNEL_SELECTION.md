# 内核版本选择与音频匹配（develop）

本功能位于 **LuCI → 服务 → AirSIM → 内核与音频**。参考
[shangjie1998/airsim-f50-openwrt](https://github.com/shangjie1998/airsim-f50-openwrt)
的固定提交 [`4df1116997425ae4b91d44cd6121bb25c836162c`](https://github.com/shangjie1998/airsim-f50-openwrt/commit/4df1116997425ae4b91d44cd6121bb25c836162c)，
采用其“查看运行内核、选择版本与本机包、生成命令、手动执行”的交互流程。
感谢 shangjie1998 的 F50 集成工作。本项目重新实现只读后端和页面，未引入其内核二进制、音频包或安装脚本，也未修改 AirSIM 客户端。

## 使用

1. 打开页面，核对“运行内核”“启动选择”和“已安装记录”。运行内核是当前真正生效的版本；其余记录可能是下次启动目标，不能混为一谈。
2. 查看当前音频方案、配置 SHA-256 和扩展目录检测结果。刷新仅查询文件，不调用 AT、DSP、音频播放或服务启停。
3. 目标版本可选 **5.4、6.18、7.3**；已知运行系列会预选，未知系列要求手动选择。选择不会修改设备。
4. 若确实要准备换内核，先取得适用于目标硬件的可信内核包并核对来源、校验值和回退方案，再放到 `/mnt/mu300-disk/pkg/` 或 `/tmp/`。页面只列出名称含 `kernel` 的非空普通 `.tar.gz` 文件，不扫描或解压包内容，也不将文件名当作可信版本声明。
5. 选择该文件，填写与它对应的上游 Release 标签，例如 `v2026.11.02.1`。标签不自动套用当前系统记录，避免把旧记录用于新目标。5.4 / 6.18 保持原生手动命令；7.3 通过下述受保护入口，默认只检查。
6. 复制命令后自行审阅、确认通话结束和回退路径，再在设备 SSH 执行。页面没有执行切换或重启的接口；重启另行安排。HTTP 页面无法使用剪贴板时可以手动选中命令复制。

刷新保留目标和标签；已消失的包会取消选择。读取失败会禁用命令复制并清除过时结果。

## 音频支持边界

| 目标内核 | 参考项目的方案 | 本项目当前情况 |
| --- | --- | --- |
| 5.4 | F50 厂商镜像已有音频驱动 | 只验证 U30 Air 的 `5.4.254-gb50db5b6224c` 和指定配置；R16 重建扩展沿用至 R23 |
| 6.18 | 独立 `6.18.60` 音频模块包 | 未引入对应包、未做 U30 Air 实机验证 |
| 7.3 | 独立 `7.3.1` 音频模块包 | 未引入对应包、未做 U30 Air 实机验证 |
| 其他内核 | 取决于对应适配 | 显示未知/无已验证包，不冒充兼容 |

已验证配置 SHA-256：`1057cb97e0d2d7f26816e8bf7841faac1153833a01d4893cdc196b75ae6356b3`。
配置摘要与原安装器同口径：解压 `/proc/config.gz`，保留 `CONFIG_` / `# CONFIG_` 行，按字节排序后计算 SHA-256。

“内核及配置匹配”只表示符合既有方案前提，不代表本机模块已安装、DSP 已就绪或通话已验收。
“检测到 R16 归档”只表示文件存在；实际安装依然检查固定哈希及签名。内核选择器不改变音频安装器的适用边界；独立音频配件卡片仍按原目录及 ABI 保护处理。

扩展目录固定为 `/mnt/mu300-disk/extra/airsim-audio/modules/`。逐目录读取 `KERNEL` 的 KREL/CONFIG，并检查所有 `.ko` 的 AArch64 ELF `.modinfo`：release 必须匹配、完整 vermagic 必须互相一致，还必须存在 `audio_reserve.ko`。同版本不同配置、损坏文件、缺元数据都会明确显示，绝不重写元数据或放行 CONFIG。

资料通过时仍显示“完整性、符号 ABI 与通话待验证”，因为目录名、配置和 vermagic 无法证明来源、全部依赖与符号 CRC 相容；原 `scripts/openwrt-audio-abi.py` 构建审核和安装保护继续保留。页面不将厂商驱动不存在于 AirSIM 目录解释为系统缺少音频，也不以 `missing=0` 代替双向验收。

## 接口与验证

- rpcd `airsim.kernel_status`：无输入参数，仅加入 LuCI 读权限。
- 设备 CLI `airsim-mu300d --manage kernel-status`：服务关闭或设置损坏时仍可读取；不新增网络监听端口。
- 只读文件数量、大小有界；内核包最多 64 个，音频目录最多 16 个。只列出归档，不解压或执行。
- 命令标签严格验证，目标来自三档白名单，路径必须来自本次列表且正确 shell 引用；控制字符路径拒绝生成命令。
- 自动化覆盖配置规范化/损坏压缩数据、未知内核、同版本配置差异、模块格式与版本冲突、启动记录分离、页面刷新失败与草稿保留、命令注入字符及 ACL。
- 本次仅开发与自动化验证。**本次 7.3 适配未安装到设备、未切换内核；7.3 启动、USB 与音频均未实机验收。此前 UI 候选的设备验证不等于本次内核适配验收。**


## 7.3 原生更新器适配（2026-11-12，develop）

参考 [F50 项目固定提交的内核矩阵](https://github.com/shangjie1998/airsim-f50-openwrt/blob/53f4291117959157c78d48cc28c4f892ac8a85a2/docs/内核矩阵.md)：旧更新器需要扩展 `KERNELS` 与 `kernel_cmd` 两处白名单。进一步核对发现 MU300 Linux `v2026.10.30.1` 的源码已经含 7.3，因此按更新器完整 SHA-256 区分处理，不能仅按系统日期或按钮判断。

| 更新器固定源码 | SHA-256 | 处理 |
| --- | --- | --- |
| `dikeckaan/mu300-linux` `c760e49e28e872cc0a51a656f36206cecaaf091f`（v2026.10.19.1） | `d2b4594130654047d9b91cedb22e8b18b888515192073ff8a94d0cc688b74a23` | 校验副本、备份原件，手动 apply 时原子写回两行补丁 |
| `dikeckaan/mu300-linux` `8aadd074673a23a7e1e37fc07cfd1dd3a7773917`（v2026.10.30.1） | `cda543e8c077e92fffbea947a4662f571a5718ae9b82fba6491801674a6df12e` | 已有 7.3，副本保持逐字节一致 |
| 其他或被修改的脚本 | 未审查 | 禁用 7.3 命令，等待源码审核；不按字符串猜测安全性 |

独立补丁为 `patches/mu300-update-7.3.patch`；补丁结果 SHA-256 为 `97a93e4fe679caf801c48dc2a5f76783692bc525883471b3892286b42dd6e3f9`。不分发完整原生更新器，原作者注释保留。仅手动 `apply` 时，将已审查旧版备份到 `/mnt/mu300-disk/extra/airsim/kernel-updater/`，再原子写回这两行补丁；已支持版本不写回。不自动撤销补丁，防止原脚本把已选择的 7.3 回落成 5.4；插件卸载保留该兼容补丁和备份。确认已回退至旧版支持的内核后，才能人工核验备份并恢复原脚本。`check`、插件安装和页面读取都不写回。每次运行重新读取本机原件；系统更新导致哈希变化时停止，不沿用旧副本。

页面选择 7.3 后需填写**可信上游发布清单中的内核包 SHA-256**。应先验证清单的签名、来源和所属 Release；自行计算未知文件的哈希不能证明来源可信。页面生成 JSON 管道命令，目标为 `/usr/lib/airsim/airsim-mu300d --kernel-7-3 check`，仅校验文件、机型和包内容。选择“写入 7.3 内核（不重启）”才生成 `apply` 和 `confirm=true`。复制命令、刷新页面、安装插件都不会执行切换；没有内核写入 RPC。

`apply` 只允许设备 SSH root 手动执行，要求先关闭 AirSIM 服务。它持有既有维护独占锁，并复用基带通话、媒体进程和短信任务空闲检查；状态未知则停止。随后将内核包复制到持久盘私有临时目录，以该副本重新校验哈希，避免校验后路径内容被替换。最多 1 GiB 压缩包、2 GiB 解压流、20,000 个条目，拒绝符号链接、硬链接、路径穿越、重复条目和损坏 gzip。要求 `./devices` 明确包含 `u30air`、`./kernel.release` 为 `7.3.x`，并有非空内核、通用 ramdisk 和模块。拒绝 F50 专用包与 7.2 / 7.30 等其他系列。

补丁不修改原生设备 ramdisk、设备声明、SD/启动槽/根分区判断、降级检查、启动镜像写入校验、`prev.*` 或 `rollback-boot`。清除调用环境中的 MU300 测试/路径覆盖变量后执行固定命令；不自动重试、不设置会强杀写盘的超时、不重启。操作失败须按原生输出检查现场，不能直接重启。成功后仍需另行安排启动验证；恢复采用原生 `mu300-update rollback-boot` 及已有设备恢复方案，不新增自动回退或远程刷分区路径。

这些检查只能证明调度与包声明一致，不能证明内核能启动或音频兼容。**7.3 U30 启动、USB、网络、回退及双向通话均待实机验证**。5.4 音频扩展的精确内核/CONFIG/符号 ABI 检查不放宽，不把 7.3.1 或未来 7.x 宣称为已验证。
