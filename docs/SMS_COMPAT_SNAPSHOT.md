# 缺少原生短信池：兼容快照接口

2026-11-24 纳入 R27 开发预览。此前候选 `0.1.0_p20261123-r26` 已安装 USB U30 Air。
已实现原生目录、E5 原生 JSON 收件库、
私有完整快照三种读取方式，以及原生发送工具缺失时的已知版本回退。**没有原始
`smspool.uc` 或故障设备版本，不能宣称已修复所有缺池固件。** 如果设备只有 SIM
中的短信，既没有下述原生存储，也没有兼容快照，本候选仍不会自行发 AT 扫描。

## 原生链路优先

每次扫描重新选择 `/etc/mu300/sms-pool/msg`、`/etc/mu300/sms/msg`。
原生空目录是有效空收件箱，不触发替代读取。原生路径存在但不可读、非目录或为符号
链接时报告失败，不用兼容数据掩盖原生错误。两种路径都不存在时，先尝试已核对的
`/etc/e5-sms/inbox.json`；该文件也不存在时才读取兼容快照。
原生目录恢复后无需重启 Agent 即可恢复原生读取。

收件扫描不创建或写入原生目录，不启动厂商脚本，不发送 AT 指令。
已有短信确认、去重、发送未知结果保护均保留。

## 原生 JSON 收件库

格式依据 [e5-sms-receive 固定源码](https://github.com/sprd-linux-devs/e5-linux/blob/fb2d3fefaffe95eba9216d874b40bcd2a523701e/openwrt/overlay/usr/libexec/e5-sms-receive)
独立实现，不复制、启动或安装其收件服务，也不声明新增 E5 硬件通话支持。

- 只读 `version: 1`、完整 `messages` 数组。受 16 MiB / 10000 条上限和私有文件权限约束。
- 仅同步 card=0（SIM 1）、direction=in、state=received、未删除的短信。
  第二张 SIM 不伪装成第一张；未完成分片不暴露给手机。
- 直接使用带时区的 `time`，若同时有 epoch，要求两者一致；不以扫描时间生成收件时间。
- 稳定 ID 结合原生持久 id、SIM 身份和正文生成摘要，已读标记、原始存储索引变化不造成重复。
  原始 SIM 身份不通过接口、日志或诊断返回。
- 确认交付仅写 Agent 自己的确认记录，不标记原生已读，不删除 SIM、原生 JSON 或分片。
- 格式损坏、版本不识别、缺失数组或重复 ID 时保留手机待交付状态并报错；不退回其他
  快照掩盖问题。只有原生明确的空数组才表示空收件库。

这是直接读取固件已维护的归档，不需要额外 `smspool.uc` 或每五秒重写一份正文。
扫描成功仅证明归档可读，不能代替原生接收服务存活或手机实际收件验收。

## 兼容生产者契约

未来经审查的固件采集适配将完整快照写到固定路径：

`/run/airsim/sms-compat/inbox.json`

该文件仅存 RAM，避免每 5 秒写闪存。目录 0700、文件 0600，由运行 Agent 的用户
拥有（设备上为 root），路径各级不允许符号链接。临时文件写完关闭，在同目录
`rename` 成 `inbox.json`；失败时保留旧快照，不写空列表冒充成功。

格式为一个 JSON 对象：

| 字段 | 契约 |
| --- | --- |
| `version` | 整数 1 |
| `complete` | 必须为 true；所有分页与底层完成状态均已确认 |
| `captured_at` | 此次完整读取成功的 Unix 秒；不是开始读取时间 |
| `messages` | 接收短信数组，明确的空数组表示完整扫描后为空；缺失/null 不接受 |
| 每条 `id` | 1–12 位数字字符串；快照内唯一，不能只以数组位置生成 |
| `from` | UTF-8 发件标识，不含 CR/LF/NUL，最多 256 字节 |
| `scts` | 原始服务中心时间字符串，最多 128 字节，不含 CR/LF/NUL |
| `received` | 首次入库的稳定 Unix 秒，正值，不晚于 captured_at；不可每轮更新 |
| `length` | 正文 UTF-8 字节数，1–65536；不是字符数 |
| `body` | UTF-8 正文，JSON 转义保留换行；不额外添加尾部换行 |

Agent 复用原生格式解析器及其 delivery_id 算法；captured_at 不参与交付 ID。
最多 10000 条、整个 JSON 最多 16 MiB。不接受未知字段、尾随 JSON、重复消息 ID、
长度不符、未来时间或不完整快照。captured_at 最多过期 30 秒或超前 5 秒；进程内
不接受快照时间倒退。读取失败保留已有待交付列表和确认记录，并报告错误。

生产者必须持久保存首次 received 与消息身份，以免重启后重复同步；SIM 索引复用
需结合发件人、原始时间及正文辨别。只有成功的完整扫描才能从兼容快照移除记录，
不得将超时/解析失败当作 SIM 删除，也不得因此删除 SIM 原文。长短信必须确认所有
分片完整，或者采用另行审查的明确不完整消息方案，不静默拼接错位内容。

建议空闲时单实例 5 秒采样；失败退避，通话/发信/切卡期间不争抢调制解调器。
若仍在保留旧快照等待重试，不刷新 captured_at 伪造新鲜度。

## 为什么没有直接运行旧 sms json

本地保存的上游实现包含 `AT+CPMS`、`AT+CMGF=0` 和 `AT+CMGL=4`。部分管道读取
错误会落入空数组输出，它不是可据此清理缓存的完整成功证明。缺少故障固件实际
接口及包装器源码时，本项目不自动执行这个命令或复制它作常驻轮询。

## 缺少原生发送包装器

优先使用已有 `/opt/mu300/bin/mu300-sms`，保留 stdin/位置参数识别；即便该文件损坏、
无执行权限、为断开的链接或执行失败，也不会换另一工具重新提交。

仅当该路径不存在时，检查设备已有的 `/opt/mu300/bin/sms` 及其依赖。以下三份文件
必须与 [dikeckaan/mu300-linux 固定提交](https://github.com/dikeckaan/mu300-linux/tree/833616a6c03a7c0245300c5946d98ec98b09bb94/rootfs/overlay/opt/mu300)
完全匹配；不下载或覆盖系统文件：

| 文件 | SHA-256 |
| --- | --- |
| `bin/sms` | `bdd3fe96ab4abf1927b7a9d17609426948dbe7904b33694b009b6c452ed82394` |
| `bin/mu300-at` | `de903956c3e86b4d88281bba2d4c985cad7832b85117710b715d6633f79f819d` |
| `lib/sms-pdu.awk` | `50f3e461a1c3bae04d528376a381843f8d775f6bb5aa20c7395385147759059b` |

文件须归 Agent 用户拥有且不可被其他用户写入；可执行文件须可执行。备用路径还需
单 broker 的命令 FIFO、有效 owner/pid 与对应进程，拒绝切卡/状态不明和 dual-radio
freeze 布局。现有通话空闲检查、发送事务、防重复提交与未知结果栅栏继续生效。

备用工具只调用一次 `send --stdin`，支持正文内部换行。该上游 shell 工具会去除末尾换行，
因此兼容路径在提交前拒绝以换行结尾的正文，避免静默改写内容。清除继承的 MU300 覆盖变量，固定
依赖和命令路径；把工具的直接设备后备地址设为不可创建的 `/proc` 路径，即使 broker
在预检后消失也不能直接打开 tty。退出失败、超时、无完整回执均不自动重发。
原生 stdout 上限 64 KiB，stderr 不输出到客户端或日志。

只在真实 `sent (reference N)` 或 `sent (N)` 回执加成功退出时确认基带接受提交；
`rc=0` 单独不足够，也不代表运营商送达。未知版本保留明确失败，不能按名称猜兼容。
这不是 E5 发送实现；其不同的 ModemManager/选卡事务没有被混用到 MU300 发送路径。

## 诊断

Agent `/api/sms/status` 增加 `backend` 对象：
`source`（native / native_json / compat / unavailable）、`last_success_at`、`compat_captured_at`。
时间为 Unix 秒，0 表示尚未成功。原生 last_success_at 仅证明文件扫描成功，不能
证明原生生产服务仍在接收新短信。`count` 是待交付数量，不是 SIM 全部短信数量。

LuCI 短信页增加单独的“AirSIM 手机短信链路”状态；经只读 ACL 的 `airsim.sms_status`
访问回环管理端口，再读取 Agent 状态。仅返回白名单状态字段，不返回号码、正文、
路径或原始错误文本。网页列表与手机数据源分别显示，避免把网页可读当作手机已同步。

符号链接拒绝、并发读取和状态脱敏。LuCI 回归覆盖原生、兼容、等待、错误及不可达。

追加合成 fixture 覆盖原生 JSON 到手机 GET/ack、时区、原生文件零写入、确认后重启
去重、换卡身份、已读/索引变化、发件/分片/删除/第二卡过滤、损坏库不清空，以及
备用发送工具哈希/权限/owner 检查、多行 stdin、原生失败不降级、直接 tty 后备禁用。

安装后管理接口和 LuCI RPC 均显示 `source=native, state=ready`，扫描成功时间正常更新，
原生池继续优先，未触发兼容采集。pending_count=0 是待交付数，不能理解为原生池没有短信。
设备内已备份旧插件与私有配置，配对/配置保留，未重启设备、改动短信原文或自动发送短信。
真实收发、故障固件实际接口、iPhone 同步仍未验收。若反馈用户没有上述任何原生存储，仍需其固件版本/接口，再接入
对应生产者；不能仅凭他曾运行 `smspool.uc` 就判断已覆盖。
