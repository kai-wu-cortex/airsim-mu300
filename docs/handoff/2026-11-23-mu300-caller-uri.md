## 已有规则和本次差异

R25 起已有 `mu300CallerNumber`，在 `mu300ApplyCallPollWithEnds` 写入记录前调用。
同一基带槽的 `mu300CallerIdentity` 使用相同投影，防止 incoming → active 由 URI
变成纯号码时换 UUID。它是蜂窝基带号码展示投影，不是通用 SIP URI 等价或拨号解析器。

本轮新增 `tel:` 数字用户、旧 Agent 的 `数字@host`、用户部分 `user=phone` 处理；补充 **trim 前拒绝原始控制字符**，防止
首尾 CR/LF 被 TrimSpace 去掉后误转成号码。保留 SIP/SIPS 原有域、IPv6、端口与参数检查。

## 与客户端对齐的具体边界

- scheme 大小写不敏感；URI 只解码用户号码部分，百分号仅解码一次，`+` 不当空格。
- 原始输入上限 512 字节；ASCII 数字最多 20 位，`+` 只在数字前出现。
- URI 号码内允许视觉分隔符 `- . ( )`；原始和解码后的内部空格均拒绝，`+` 只能在第一位。
- 保留 `+` 与 `00` 原意，不相互改写，也不从 IMS 域推断国家或区号。
- SIP/SIPS 及省略 scheme 的格式仅允许一个 `@`，数字 subscriber 不含密码或 header；host 只校验不解析 DNS。
- 用户或 host 部分只允许 `user=phone`、`transport=udp|tcp|tls`，跨两部分检测重复参数。
  其他参数保持原文；此轮没有扩大 transport 白名单。
- TEL 支持无参数形式或单个 `user=phone`，不接受 transport 或其他参数。
- `phone-context`、`ext`、`isub` 不可删除；匿名/字母用户、空号码、多个 `+`、畸形编码、
  二次编码、原始或解码后控制字符、非 ASCII 数字都不能投影成数字。
- 未识别值保持不透明地址。原始控制字符不先 trim；普通外围空格仍沿用旧行为。
- 不改变 `normalizeDialNumber`、短信目标校验、认证或生成 UUID 的逻辑。

客户端本地旧历史的显示和联系人匹配需由客户端侧处理。完整 Agent race/vet 和 ARM64
构建已通过；从仓库保存基线重新应用补丁后，97 个 Go 文件及共享 fixture 与测试版本一致。
本轮仅改变号码投影、其测试和 fixture 三个 Agent 文件。真实跨端来电仍需用户验收。

共享 fixture 从 AirSIM `tests/caller-number-cases.json` 复制到隔离 Agent 的
`testdata/caller-number-cases.json`，33 个合成用例逐项校验，随补丁保存，不依赖相邻仓库。
MU300 额外覆盖首尾 CR/LF、控制字符、解码后空格、跨两部分重复参数等边界；客户端
